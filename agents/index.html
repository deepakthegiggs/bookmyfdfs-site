    Use FDFS from an assistant or agent

    Updated 28 Nov 2026, 07:24 IST

    Your assistant or agent can query our 54 checked offers. Connect the read-only FDFS MCP server by its address, or read the open feeds.

    2. For agents

    MCP server

    FDFS has a small Model Context Protocol (opens in a new tab) server, so an assistant or agent can answer "which of my cards gets me a deal on this booking?" from our checked offers. Each answer has the cap, the key condition, the end date, the official source, when we checked it, a message ready to send your group, and a link to the offer's page here.

    Connect by address (nothing to install)

    Add this address as a custom connector in your assistant (it speaks Streamable HTTP, no sign-in):

    https://fdfs-mcp.deepakthegiggs.workers.dev/mcp

    In Claude Code: claude mcp add --transport http fdfs https://fdfs-mcp.deepakthegiggs.workers.dev/mcp

    Or run it yourself

    1. Download fdfs_mcp.py. It's one file, standard-library Python 3.9 or later, read-only.
    2. Add it to your MCP client (Claude Desktop, Claude Code, Cursor and others take the same shape):
      {"mcpServers": {"fdfs": {"command": "python3", "args": ["/path/to/fdfs_mcp.py"]}}}

    Then ask about movie ticket offers, for example "I have Axis My Zone and HDFC Diners Club Privilege. Which one for 2 tickets on District this Saturday?"

    Tools

    • match_cards: the cards in your wallet, plus the app, day and number of tickets if you know them. For each card, the offers it qualifies for, best first, and whether the terms name that card or only its bank.
    • find_offers: every checked offer, by day, app, bank or free text.
    • get_offer: one offer's full recorded terms, with the quotes from the official page.
    • list_banks: which banks have checked offers now, and on which apps.

    Both read /offers.json and nothing else. The downloaded script keeps the cards you name on your computer. The hosted server gets only what your assistant sends it, uses it to answer, and keeps no record. It never returns spotted leads, leaves out offers past their end date, and flags any offer we haven't re-checked in 7 days.

    Data feeds

    • offers.json: every checked offer with its source, quotes and check time (CC BY 4.0).
    • llms-full.txt: the same offers as plain text.
    • llms.txt: our key pages, for answer engines.
    • changes.json and changes.xml: what changed, dated.

    Using our data

    Credit "FDFS (bookmyfdfs.in)" and link the offer's page (each offer's url). Say when we checked it, and tell people to read the terms before they pay: quotas and spend rules can't be checked from outside.
